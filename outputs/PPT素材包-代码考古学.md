## 4. 三个"故事点"（路演最有杀伤力的部分）

### ① 护城河：先进后出，代码里零痕迹

`oa-system` 的 `b86cce0`（05-29 12:51「feat: 集成邮件发送功能（Resend）」route.ts **+58**）
→ `7c78ec0`（05-29 13:43「fix: 清理不需要的邮件相关代码和依赖」route.ts **−58**）。

**间隔 52 分钟**，提交信息清晰，代码里零痕迹 —— 这是只有读历史才能得到的结论，
而且假设层给了「中」置信度、写明「可能因为…」的推测限定。**demo 只挑这类能自证的案例。**

### ② 最大的技术亮点：我们证伪了自己

原先的判定只看**净删行数**，不看内容。于是 chalk 的一次 `Improve performance` 重写被读成
「下划线样式被放弃」——而该功能至今是 chalk 的**核心特性**（`index.d.ts` 里 `underlineRgb`
/ `underlineHex` / `underlineAnsi256` / `underlineCurly` 全在）。

修复方式：新增 `src/core/overlap.js`，把判定从「按行数猜」升级为「按内容判」：
- 内容核实：拆除侧删除的行在新增侧出现的比例 ≥ 50% 才算放弃
- 排除整仓回滚：提交信息匹配 `^restored?\s+to\s+'?[0-9a-f]{7,40}` 的，连带删除单列
- 容错：拿不到 patch 时**不下判断**，保留为待核实线索（不可核实 ≠ 假阳性）

效果：chalk 风险分 **63（高）→ 55（中）**，降幅全部来自假阳性被剔除；
**oa-system 的 Resend 真阳性完整保留**。四个真实案例已固化为回归测试。

**路演怎么讲**：这一步需要能证伪自己的勇气。我们没有把假阳性藏起来，
而是把「复核未通过」的判定一并亮在页面上 —— 只展示「发现了什么」、不展示「否定了什么」
的报告无法被复核。

### ③ 幻觉检测不靠模型，靠代码（这是我认为最关键的设计）

常见做法是「让另一个模型检查前一个模型有没有胡说」—— 但判官本身也会幻觉，而且它无法查证。

我们的做法：模型产出的每一条结论都必须引用具体的 commit SHA，而这些 SHA 是我们从
GitHub 真实拉回来的。于是「引用了一个不存在的 SHA」可以被**一次集合运算**直接判定 ——
这是**可证明的编造**，不是主观判断。这一步 100% 由程序完成，不经过任何模型。

## 7. 评委问答预案（按被问概率排序）

**Q1｜你怎么知道你猜的对？**（几乎必问）
> 我们不猜。系统只承诺可验证的东西：含糊提交率、无痕迹的被放弃改动、巴士因子、沉寂断层。
> 推断层必须标置信度，证据含糊时强制写明「提交信息未说明原因，以下为基于改动范围的推断」，
> 而且每条结论都过 SHA 集合校验。判断权交回给人。

**Q2｜和 CodeScene / git-of-theseus / Hercules 有什么区别？**
> 它们做行为码分析：hotspot、bus factor、knowledge map、团队效能。我们的差异化只有一条：
> **「被放弃的尝试」** —— 代码中不存在、只能从历史里挖出的信息。我们承认这条护城河很窄，
> 所以把它做扎实：内容级核实 + 唯一性自我证伪。

**Q3｜私有仓库看不了，尽调场景不就废了？**
> 对，这是已知边界，我们把它写在 PPT 第 5 页而不是等你问。当前架构依赖 GitHub REST API。
> 产品化的正道是本地 `git log`：零 API 成本、完整历史、不碰对方凭据。这是下一步。

**Q4｜三个模型有必要吗？一个模型换 prompt 不行？**
> 不行，因为我们的依赖是**串行有依赖**而非并行投票：叙事者把 diff 变成过程，假设者据此推断
> 意图，审稿人拿到**代码层校验结果**再回头质疑前两者。它可以说出「这条结论引用了不存在的
> 提交」，而不是含糊地说「可能不准」。单模型换 prompt 做不出这个校验闭环。而且并行编排后
> 全流程 20.6 秒（chalk），不比串行慢。

**Q5｜是不是套用现成项目？**（扣分项触发问）
> 零依赖框架：前端是零构建原生 JS，后端是 Cloudflare Workers 原生 fetch。核心模块
> `core/overlap.js`、`core/noise.js`、`core/message.js`、`agents/verify.js` 全部自研，
> 8997 行自有代码，165 个自写测试。

**Q6｜数据是真的吗？**（扣分项触发问）
> 零预置数据，没有一条合成 fixture 出现在演示路径上。你可以现在报一个仓库名，我们当场跑。

**Q7｜商业模式？**
> 三种形态对应三种收费可能：CI 闸门（最可能先变现，SaaS 化按仓库数订阅）、
> 尽调报告（按次交付）、交接清单（团队版功能）。

**Q8｜为什么不做 PR / issue 读取？**
> 刻意的取舍。24 小时里我们优先保住「不幻觉」，而不是扩大证据面。接入 PR/issue 会把
> 「为什么」从推测升级为引用，是明确的下一步。
